### ③ Harness 원본의 락을 잡고 복사한다

```
# 락을 쥔 채로 VACUUM INTO — 수집기가 다시 깨어나도 끼어들 수 없다
python3 - <<'PY'
import fcntl, sqlite3, time
from pathlib import Path
H = Path("/Users/seongjin/Coding/Harness for K-Politics/.claude/skills")
D = Path("/Users/seongjin/Coding/Skills for K-Politics/.claude/skills/k-politics/DBs")
쌍 = [(H/"congress/CONGRESS.db", D/"CONGRESS.db"), (H/"law/LAW.db", D/"LAW.db")]
잠금 = []
try:
    for 원본, _ in 쌍:                      # 고정 순서: 국회 → 법령
        f = Path(str(원본) + ".lock").open("a+")
        fcntl.flock(f.fileno(), fcntl.LOCK_EX)   # 블로킹 — 도는 수집이 끝날 때까지 기다린다
        잠금.append(f)
    for 원본, 대상 in 쌍:
        대상.unlink(missing_ok=True)
        c = sqlite3.connect(f"file:{원본}?mode=ro", uri=True)
        t = time.monotonic()
        c.execute("VACUUM INTO ?", (str(대상), ))
        c.close()
        print(f"{대상.name} {대상.stat().st_size/2**30:.2f}GiB {time.monotonic()-t:.0f}초")
finally:
    for f in reversed(잠금):
        fcntl.flock(f.fileno(), fcntl.LOCK_UN); f.close()
PY
```

### ④ 원본과 표별 행 수가 같은지 대조한다

```
python3 - <<'PY'
import sqlite3
from pathlib import Path
H = Path("/Users/seongjin/Coding/Harness for K-Politics/.claude/skills")
D = Path("/Users/seongjin/Coding/Skills for K-Politics/.claude/skills/k-politics/DBs")
for 원본, 대상 in [(H/"congress/CONGRESS.db", D/"CONGRESS.db"), (H/"law/LAW.db", D/"LAW.db")]:
    a = sqlite3.connect(f"file:{원본}?mode=ro", uri=True)
    b = sqlite3.connect(f"file:{대상}?mode=ro&immutable=1", uri=True)
    assert b.execute("PRAGMA integrity_check").fetchone()[0] == "ok", 대상
    표 = [r[0] for r in a.execute("SELECT name FROM sqlite_master WHERE type='table'")]
    어긋남 = {t: (x, y) for t in 표
              if (x := a.execute(f'SELECT COUNT(*) FROM "{t}"').fetchone()[0])
              != (y := b.execute(f'SELECT COUNT(*) FROM "{t}"').fetchone()[0])}
    print(대상.name, "표", len(표), "어긋남", 어긋남 or "없음")
    assert not 어긋남
PY
```

**판정:** 두 파일 다 `integrity_check` ok, 어긋남 없음.

### ⑤ 새 경로에서 백업 한 세대를 만들고, 스키마를 이 레포 것으로 맞춘다

⚠️ **Harness 세대로는 새 경로의 이행이 승인되지 않는다.** 이행 검증이 곁기록의 **원본 절대
경로**를 비교하기 때문이다. 기존 곁기록을 고쳐 우회하지 마라 — 그 검사가 지키는 것이
"백업이 겨눈 파일과 수집기가 겨눈 파일이 갈리는" 사고다.

⚠️ **`migrate` 를 빼면 A0 가 재현된다.** 복사본은 Harness 의 옛 주석을 그대로 들고 오는데
이 레포의 SCHEMA 상수는 독자용으로 고쳐져 있어서, 복사 직후의 DB 는 상수와 갈린 상태다.
`init` 은 뷰(`신선도` 포함)를 다시 세우고 `migrate` 는 주석만 바뀐 DDL 을 갈아 끼운다.
순서는 **백업 → init → migrate → 감사**이고, `migrate` 의 백업 게이트가 첫 줄을 요구한다.

```
cd "$레포/.claude/skills/k-politics"
uv run Scripts/backup.py congress --이행직전
uv run Scripts/backup.py law --이행직전
uv run Scripts/congress/db.py init && uv run Scripts/congress/db.py migrate
uv run Scripts/law/load.py init && uv run Scripts/law/load.py migrate
uv run Scripts/congress/audit.py
uv run Scripts/law/audit.py
```

**판정:** 각 코퍼스에 새 경로 기준 세대 1개 · 감사 국회 15/15 · 법령 24/24 ·
`SELECT * FROM 신선도` 가 두 파일에서 각각 한 행.

## 이 절차를 쓰다가 겪은 것 (2026-09-12)

**`git checkout main` 이 스냅샷을 지웠다.** `법.db` 는 gitignore 지만 **초기 커밋에 0바이트로
추적돼 있었다.** 브랜치를 그 커밋 쪽으로 옮기는 순간 git 이 4.6GB 를 0바이트로 덮어썼고,
뒤이은 `pull` 이 (머지가 그 파일을 삭제했으므로) 아예 지웠다.

**한 번 추적된 적 있는 파일은 gitignore 에 넣어도 브랜치 전환에서 안전하지 않다.**
스냅샷은 3분이면 다시 만들어지니 실손은 없었지만, 원천에는 이 규칙이 그대로 적용되면 안 된다 —
`DBs/원천/` 은 **한 번도 추적된 적이 없어야 한다.** C4 이후
`git ls-tree -r HEAD --name-only | grep 원천` 이 0건인지 확인해라.

**옮기자마자 버그 둘이 나왔다 — 옮기지 않았으면 못 봤을 것들이다.**

- **A0(상수와 DB 가 갈렸다).** P1b 가 `law/schema.py` 의 주석 속 `직결.py` 를 `direct.py` 로
  고쳤는데 라이브 DB 는 안 고쳤다. 그대로면 **매일 감사가 빨간불**이고, 그게 이 레포가 기록한
  "매일 같은 빨간 X 가 신호를 죽였다"의 재현이다. 백업 세대 → `load.py migrate` 로 닫았다.
- **`신선도` 가 감사 시각을 안 담았다.** 감사는 수집 파이프라인이 돌 때만 원장에 기록되므로
  (`audit.py` 를 손으로 돌려도 안 쓴다), 결과만 담으면 8일 전 실패가 오늘 실패로 읽힌다.
  `감사시각` 컬럼을 넣었다.

**교훈:** 스킬이 남의 레포 데이터를 읽는 동안에는 "코드가 가리키는 경로"가 한 번도 검증되지
않는다. 자기 원천을 갖는 순간이 그 경로가 처음 밟히는 순간이고, 거기서 막힌 것들이 나온다.
